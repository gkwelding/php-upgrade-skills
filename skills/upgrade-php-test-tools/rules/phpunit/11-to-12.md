## PHPUnit 11 to 12

Source: `ChangeLog-12.0.md` and `ChangeLog-12.5.md`, checked by running tests against PHPUnit 11.5.56 and 12.5.37. PHPUnit 12 needs PHP 8.3. If 11.5 was clean under `--display-all-issues`, this step is a constraint change. If it wasn't, PHPUnit 12 fails in ways that are easy to miss.

### Doc-Comment Metadata Is Ignored, Silently

PHPUnit 12 removed support for annotations. It doesn't warn about them; it ignores them.

```php
/** @test */
public function it_sends_the_invoice(): void   // 12: not a test any more. Not run, not counted.

/** @dataProvider amounts */
public function testTotal(int $amount): void   // 12: run without data: ArgumentCountError
```

On a sample class with four tests, PHPUnit 11 reported 5 tests (one provider with two rows); PHPUnit 12 reported 3: the `@test` method vanished and the `@dataProvider` test errored. A suite can go "green" on 12 with a fraction of its tests running. Before bumping:

```
grep -rnE "@(test|dataProvider|depends|group|covers|uses|testWith|requires|runInSeparateProcess|backupGlobals|before|after|beforeClass|afterClass)\b" tests
```

Convert every hit to attributes on 11.5 (`10-to-11.md`), and compare the test count after the bump with the count on 11.

### Removed

| Removed in 12 | Replacement |
|---|---|
| `expects()` on test stubs | `createMock()` if the expectation matters; otherwise drop `expects()`. On 12 it's `Error: Call to undefined method ...::expects()` |
| `$this->returnValue()`, `onConsecutiveCalls()`, `returnCallback()`, `returnValueMap()`, `returnArgument()`, `returnSelf()` | `willReturn()`, `willReturnOnConsecutiveCalls()`, `willReturnCallback()`, `willReturnMap()`, `willReturnArgument()`, `willReturnSelf()` |
| `getMockForAbstractClass()`, `getMockForTrait()`, `getObjectForTrait()`, `getMockFromWsdl()`, `createTestProxy()` | `createMock()` / `getMockBuilder()` on an interface or concrete class |
| `MockBuilder::addMethods()` and the proxying, autoload, unknown-type and argument-cloning toggles | none; `onlyMethods()` for existing methods |
| `iniSet()`, `setLocale()` | set and restore in `setUp()` / `tearDown()` yourself |
| `assertStringNotMatchesFormat()`, `assertStringNotMatchesFormatFile()` | none |
| Comma-separated values for `--group`, `--exclude-group`, `--covers`, `--uses`, `--test-suffix` | repeat the option |
| `restrictDeprecations` on `<source>` | `ignoreSelfDeprecations`, `ignoreDirectDeprecations` or `ignoreIndirectDeprecations` on `<source>` (present in the 11.5 schema) |
| `#[CoversClass]` / `#[UsesClass]` pointing at a trait | `#[CoversTrait]` / `#[UsesTrait]` |

`assertContainsOnly()`, `assertNotContainsOnly()`, `containsOnly()` and `isType()` are hard-deprecated in 12 and removed in 13 (`10-to-11.md` lists the replacements).

`shortenArraysForExportThreshold` now defaults to `10`, so failure diffs of large arrays are truncated. That's output only.

### 12.5: Mocks Without Expectations

From 12.5.0, a test that creates a mock object and configures no expectation on it triggers a PHPUnit notice:

```
No expectations were configured for the mock object for Mailer. Consider refactoring your test code
to use a test stub instead. The #[AllowMockObjectsWithoutExpectations] attribute can be used to opt
out of this check.
```

**Incorrect:** a mock used only to return values.

```php
$mailer = $this->createMock(Mailer::class);
$mailer->method('send')->willReturn(true);
```

**Correct:** a stub.

```php
$mailer = $this->createStub(Mailer::class);
$mailer->method('send')->willReturn(true);
```

Keep `createMock()` where the test calls `expects()`. Mocks created in `setUp()` or a base class for some tests only are the usual source of many notices; the opt-out `#[AllowMockObjectsWithoutExpectations]` exists from 12.5.2 on classes and from 12.5.4 on methods. Prefer fixing the doubles; use the attribute when a shared fixture really needs a mock for some tests and not others. Rector's composer-based PHPUnit set converts many cases (`shared/rector.md`).

`with()` without `expects()` triggers the same notice from 12.5.11 and is hard-deprecated in 13.0.2. `$this->any()` is soft-deprecated from 12.5.5 and hard-deprecated in 13: use a stub, or a real count.

### Laravel and Pest

Laravel 11, 12 and 13 support PHPUnit 12. In Pest projects this step is Pest 4 (`pest/pest-upgrades.md`).
