## PHPUnit 12 to 13

Source: `ChangeLog-13.0.md` and `DEPRECATIONS.md`, checked by running tests against PHPUnit 12.5.37 and 13.4.0. PHPUnit 13 needs **PHP 8.4.1**. Laravel 13 supports PHPUnit `^13.0.3`; Laravel 12 and earlier don't list 13. Pest 5 is built on PHPUnit 13.

### Removed

| Removed in 13 | Replacement |
|---|---|
| `assertContainsOnly()`, `assertNotContainsOnly()`, `containsOnly()` | `assertContainsOnlyString()`, `assertContainsOnlyInstancesOf()`, `assertContainsNotOnly*()`, ... (11.5+) |
| `Assert::isType()` | `isString()`, `isInt()`, `isArray()`, ... (11.5+) |
| `#[RunClassInSeparateProcess]` | no direct equivalent; `#[RunTestsInSeparateProcesses]` isolates each test instead |
| `#[CoversNothing]` on a test method | on the class only |
| `--dont-report-useless-tests` | `beStrictAboutTestsThatDoNotTestAnything="false"` in XML if that's the intent |
| Version strings without an operator in `#[RequiresPhp('8.4')]` and friends | `#[RequiresPhp('>= 8.4.0')]`: an operator and a full major.minor.patch version |

**Watch the bare version strings.** On PHPUnit 12, `#[RequiresPhp('8.4')]` is a deprecation and, on PHP 8.5, skips the test ("PHP 8.4 is required"). On 13 the requirement is ignored with a warning and the test runs everywhere. `'>= 8.4'` without a patch level is an "incomplete version requirement" warning on both.

### Hard Deprecations to Clear on 13

- **`$this->any()`**: use a stub (`createStub()` + `method()`), or a real expectation such as `atLeastOnce()`.
- **`with*()` without `expects()`** (13.0.2): either configure an invocation count with `expects()` or use a stub without `with()`.
- **`atLeast(0)`** or any non-positive argument (13.0.2).
- **Runner options** (13.2 to 13.4): `--order-by duration` / `size` become `duration-ascending` / `size-ascending`; `--cache-result` / `cacheResult` become `--record-test-run-history` / `recordTestRunHistory` (13.3); `depends` / `no-depends` in `--order-by` become `--resolve-dependencies` / `--ignore-dependencies`. Check CI scripts and `phpunit.xml`.

Soft-deprecated (no output yet, but planned): `expectExceptionMessage()` in favour of `expectExceptionMessageIsOrContains()` (13.2). Rector's composer-based set renames it once 13.2 is installed; that's optional churn, so ask before applying it across the suite.

### New: `withParameterSetsInOrder()`

PHPUnit 13 adds a direct replacement for the `withConsecutive()` pattern:

```php
$sender->expects($this->exactly(2))
    ->method('send')
    ->withParameterSetsInOrder(['a@example.com'], ['b@example.com'])
    ->willReturn(true);
```

Each argument is one call's parameter list; calls in a different order fail with "Parameter $to for invocation ... does not match expected value". `withParameterSetsInAnyOrder()` ignores order. Both exist only on 13: don't use them in code that must also run on 12, and don't rewrite working `willReturnCallback()` replacements just to use them unless asked.

Also new: sealed test doubles and a configuration option requiring sealed mocks; `assertArraysAreIdentical()` and related array assertions.
