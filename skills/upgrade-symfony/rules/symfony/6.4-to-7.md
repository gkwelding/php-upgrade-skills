## Symfony 6.4 to 7.x

Source: `UPGRADE-7.0.md` and the 7.1 to 7.4 UPGRADE files from `symfony/symfony`, checked against framework-bundle 6.4.47 and 7.4.20. Symfony 7.4 needs PHP 8.2. Do the deprecation work on 6.4 first (`deprecation-workflow.md`).

### Annotations Are Gone

7.0 removed the Doctrine annotations integration from FrameworkBundle, Routing, Serializer and Validator. `@Route`, `@Assert\...`, `@Groups`, `@ORM\...` in docblocks are ignored or fail.

**Incorrect:**

```php
/**
 * @Route("/orders/{id}", name="order_show", methods={"GET"})
 */
public function show(Order $order): Response
```

**Correct:**

```php
use Symfony\Component\Routing\Attribute\Route;

#[Route('/orders/{id}', name: 'order_show', methods: ['GET'])]
public function show(Order $order): Response
```

Use `Symfony\Component\Routing\Attribute\Route` (exists from 6.4). `Symfony\Component\Routing\Annotation\Route` still works in 7.x but is deprecated in 7.4 and removed in 8.0. Do the conversion on 6.4 with Rector: `->withAttributesSets(symfony: true, doctrine: true)` plus `->withComposerBased(symfony: true)`, which renames `Annotation\Route` to `Attribute\Route`. Doctrine mapping config must say `type: attribute` once entities use attributes. Removed config: `framework.validation.enable_annotations` and `framework.serializer.enable_annotations` (use `enable_attributes`).

### Return Types

7.0 added native return types throughout. Classes extending Symfony classes or implementing its interfaces need them, or PHP fails with "Declaration ... must be compatible". On 6.4 this shows as deprecations; fix them with `vendor/bin/patch-type-declarations` (`deprecation-workflow.md`) or Rector's composer-based Symfony set. Typical: voters, normalizers, form types and data transformers (`transform(mixed $value): mixed`), event subscribers (`getSubscribedEvents(): array`), user providers, `UserInterface::getRoles(): array`.

### Config Defaults That Changed in 7.0

Apply to options the app doesn't set. Each is a behaviour change:

| Option | Before 7.0 | 7.0+ |
|---|---|---|
| `framework.http_method_override` | `true` | `false` |
| `framework.handle_all_throwables` | `false` | `true` |
| `framework.php_errors.log` | `'%kernel.debug%'` | `true` |
| `framework.session.cookie_secure` | `false` | `auto` |
| `framework.session.cookie_samesite` | `null` | `'lax'` |
| `framework.session.handler_id` | `'session.handler.native'` | `null` if `save_path` unset, else `'session.handler.native_file'` |
| `framework.uid.default_uuid_version` / `time_based_uuid_version` | `6` | `7` |
| `framework.validation.email_validation_mode` | `'loose'` | `'html5'` |

`http_method_override: false` breaks HTML forms that send `_method=DELETE` / `PUT`: the request arrives as `POST` and routes restricted to `DELETE` return 405. If the app relies on it, set `http_method_override: true` explicitly. The 6.4 recipe's `framework.yaml` already sets `http_method_override: false`; older projects may not, so check before assuming.

Also silent: date, datetime and time form types default `widget` to `single_text`; ExpressionLanguage `in` / `not in` compare strictly; `ParameterBag::getInt()` / `getBool()` no longer fall back to `0` / `false` on invalid values (they throw `UnexpectedValueException`).

### Removed APIs to Grep For

| Removed | Replacement |
|---|---|
| `AbstractController::renderForm()` | `render()` with the form |
| `Request::getContentType()` | `getContentTypeFormat()` |
| `HttpKernelInterface::MASTER_REQUEST` | `MAIN_REQUEST` |
| `MessageHandlerInterface`, `MessageSubscriberInterface` | `#[AsMessageHandler]` |
| `ContainerAwareInterface`, `ContainerAwareTrait` | dependency injection |
| `Command::$defaultName`, `$defaultDescription` | `#[AsCommand]` |
| `#[MapDecorated]` | `#[AutowireDecorated]` |
| `@required` annotation | `#[Required]` (`Symfony\Contracts\Service\Attribute\Required`) |
| `ArgumentValueResolverInterface` | `ValueResolverInterface` |
| `ContextAwareNormalizerInterface`, `ContextAwareDenormalizerInterface`, `CacheableSupportsMethodInterface` | `NormalizerInterface` / `DenormalizerInterface` with `getSupportedTypes()` |
| `Symfony\Component\Security\Core\Security` (deprecated 6.2) | `Symfony\Bundle\SecurityBundle\Security` |
| `Email::attachPart()` | `addPart()` |
| `translation:update` command | `translation:extract` |
| Templating component | Twig |
| `!php/const:` YAML tag | `!php/const` |

Normalizers and denormalizers must implement `getSupportedTypes(?string $format): array` in 7.0. Several core normalizers became `final`: decorate them instead of extending.

SecurityBundle: enabling the bundle without configuring at least one firewall is an error; `enable_authenticator_manager` was removed (remove the key).

### Inside 7.x

7.1 to 7.4 are minors, but each deprecates things 8.0 removes. Notable `[BC BREAK]` items: 7.1 moved `EmojiTransliterator` to `symfony/emoji`; 7.4 `CurrencyType` lists only active legal-tender currencies by default. Read each skipped minor's UPGRADE file. 7.1 also deprecates Doctrine entity auto-mapping in controllers and 7.3 deprecates constraint option arrays; both become errors in 8.0 (`7-to-8.md`), so fix them while on 7.4.
