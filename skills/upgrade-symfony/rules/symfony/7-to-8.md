## Symfony 7.4 to 8.x

Source: `UPGRADE-8.0.md`, `UPGRADE-7.4.md` and `UPGRADE-8.1.md` from `symfony/symfony`, checked against framework-bundle 7.4.20 and 8.1.8, doctrine-bundle 3.3. 8.0 is 7.4 without its deprecations: clear every 7.x deprecation on 7.4 first (`deprecation-workflow.md`), then bump.

### PHP 8.4

Symfony 8 requires PHP 8.4 (`symfony/framework-bundle` 8.1 requires `>=8.4.1`). If the deploy target is older, stop at 7.4 (an LTS release) and report.

### XML Configuration Is Removed

7.4 deprecated XML for service and routing configuration; 8.0 has no `XmlFileLoader` in DependencyInjection or Routing. `config/services.xml`, `config/routes/*.xml` and XML imports must become YAML, PHP or attributes before the bump. The routing XML files FrameworkBundle and WebProfilerBundle shipped (`errors.xml`, `webhook.xml`, `profiler.xml`, `wdt.xml`) are gone too: import the PHP versions. Validator and serializer XML mapping still exist, but 8.0 removes implicit constraint options in validator XML and YAML (name each option, see the UPGRADE file).

Fluent PHP config builders (`return function (AcmeConfig $config) { $config->color('red'); };`) are deprecated in 7.4 and removed in 8.0; the 8.0 UPGRADE file shows returning the config as an array instead.

### Validator Constraints Take Named Arguments

Passing an options array to a constraint is deprecated in 7.3 and fails in 8.0, both as `new` and as an attribute.

**Incorrect:**

```php
#[Assert\Length(['min' => 3, 'max' => 100])]
#[Assert\Choice(['draft', 'published'])]
```

7.4: deprecation. 8.1: `TypeError: Length::__construct(): Argument #1 ($exactly) must be of type ?int, array given`.

**Correct:**

```php
#[Assert\Length(min: 3, max: 100)]
#[Assert\Choice(choices: ['draft', 'published'])]
```

Named arguments work on 6.4 and 7.x, so this can be done early. Rector: `ConstraintOptionsToNamedArgumentsRector` (in `withComposerBased(symfony: true)` from validator 7.3). Custom constraints must initialise their own properties in the constructor; 7.4 adds `#[HasNamedArguments]` for that and the UPGRADE-7.4 file shows the pattern. `getRequiredOptions()` and `getDefaultOption()` are removed in 8.0. Defaults also changed: `Url` constraint `requireTld` defaults to `true`; `UrlType` `default_protocol` defaults to `null` (no more `http://` prefixing; set `'default_protocol' => 'http'` to keep it).

### Doctrine Entities in Controllers Need Explicit Mapping

Auto-mapping (any route parameter matching an entity field becomes a `findOneBy()` criterion) was deprecated in DoctrineBridge 7.1 and removed in 8.0. DoctrineBundle 3 only accepts `doctrine.orm.controller_resolver.auto_mapping: false`.

`{id}` (or a parameter named like the argument) still resolves by primary key. Other parameters need mapping.

**Incorrect:**

```php
#[Route('/products/{slug}')]
public function show(Product $product): Response
```

**Correct:** a mapped route parameter (7.1+), or `#[MapEntity]`:

```php
#[Route('/products/{slug:product}')]
public function show(Product $product): Response

// or
#[Route('/products/{slug}')]
public function show(#[MapEntity(mapping: ['slug' => 'slug'])] Product $product): Response
```

### Security

- **`eraseCredentials()`** is deprecated in 7.3 and removed from `UserInterface` and `TokenInterface` in 8.0. If it cleared a plain-password property, do that in `__serialize()` (UPGRADE-7.3 shows the pattern). Rector: `RemoveEraseCredentialsRector` (security-core 8.0).
- **Voters**: `Voter::voteOnAttribute()` gains a fourth parameter. On 8.x the abstract method is `voteOnAttribute(string $attribute, mixed $subject, TokenInterface $token, ?Vote $vote = null): bool`; a voter without the parameter is a fatal signature error. Add `?Vote $vote = null` on 7.4 (allowed there) before the bump. `Vote` is `Symfony\Component\Security\Core\Authorization\Voter\Vote`. Rector: `AddVoteArgumentToVoteOnAttributeRector`.
- **`hide_user_not_found`** is removed: `true` becomes `expose_security_errors: 'none'`, `false` becomes `'all'`.
- `UserBadge` with an empty user identifier throws `BadCredentialsException`; callable firewall listeners are removed; the OIDC handler's `algorithm` / `key` options became `algorithms` / `keyset`.

### Console

- `Command::getDefaultName()` / `getDefaultDescription()` are removed: use `#[AsCommand('app:create-user', 'Creates users')]`. `#[AsCommand]` is `final`.
- `Application::add()` is removed: `addCommand()`.
- Closures passed to `setCode()` need typed parameters and an `int` return.

### Other Removals to Grep For

| Removed in 8.0 | Replacement |
|---|---|
| `Request::get()` | `$request->attributes`, `->query` or `->request` explicitly |
| `#[TaggedIterator]`, `#[TaggedLocator]` | `#[AutowireIterator]`, `#[AutowireLocator]` |
| `!tagged` YAML tag | `!tagged_iterator` |
| `Symfony\Component\Routing\Annotation\*` | `Symfony\Component\Routing\Attribute\*` |
| `PropertyInfo\Type`, `getTypes()` on extractors | `symfony/type-info` `Type`, `getType()` |
| `NameConverterInterface::normalize(string $propertyName)` | gains `?string $class, ?string $format, array $context` |
| `TranslatableMessage::__toString()` | `trans()` or `getMessage()` |
| `LazyGhostTrait`, `LazyProxyTrait` | PHP 8.4 native lazy objects |
| `Workflow\Event::getWorkflow()` | inject the workflow (`#[Target('name')] WorkflowInterface`) |
| `RateLimiterFactory` autowiring aliases | `RateLimiterFactoryInterface` |

HTTP method override is ignored for `GET`, `HEAD`, `CONNECT` and `TRACE`. Several classes became `final` (FrameworkBundle `Router`, `Translator`, cache warmers): decorate instead of extending.

### 8.0 to 8.1

A minor. Read `UPGRADE-8.1.md` for its `[BC BREAK]` items and run Rector's composer-based Symfony set again after the update: it has rules bound to 8.1 (filesystem, security-http, uid, validator).
