## Laravel 10 to 11

Source: the official 11.x upgrade guide, checked against `laravel/framework` 10.50 and 11.57 and the `laravel/laravel` 10.x and 11.x skeletons.

### Keep the Application Structure

Laravel 11 ships a slimmer skeleton (`bootstrap/app.php` configuring routing, middleware and exceptions; no `app/Http/Kernel.php`, `app/Console/Kernel.php`, `app/Exceptions/Handler.php`, most service providers gone). The official guide says Laravel 10 applications should **not** migrate to it as part of the upgrade: Laravel 11 runs the Laravel 10 structure unchanged.

**Incorrect:** deleting `app/Http/Kernel.php` and rewriting `bootstrap/app.php` as step one of "upgrade to 11".

**Correct:** keep the existing kernels, providers and `bootstrap/app.php`. Migrate the structure only if the user asks, as a separate step after 11 is green (`slim-skeleton.md`).

### Dependencies

PHP 8.2 and curl 7.34 or newer. In `composer.json`:

| Package | Constraint |
|---|---|
| `laravel/framework` | `^11.0` |
| `nunomaduro/collision` | `^8.1` (collision 7 conflicts with `laravel/framework >=11`) |
| `laravel/sanctum` / `passport` / `cashier` / `telescope` / `spark-stripe` | `^4.0` / `^12.0` / `^15.0` / `^5.0` / `^5.0` |
| `laravel/breeze` / `jetstream` / `dusk` / `octane` / `scout` | `^2.0` / `^5.0` / `^8.0` / `^2.3` / `^10.0` |
| `livewire/livewire` / `inertiajs/inertia-laravel` | `^3.4` / `^1.0` |

Only bump the ones installed. Remove `doctrine/dbal` if it was only there for Laravel's column changes (ask), and remove `spatie/once` (Laravel 11 has its own `once()`; the package conflicts).

PHPUnit can stay on 10: `laravel/framework` 10 conflicts with `phpunit/phpunit >=11`, Laravel 11 supports 10.5 to 12. Moving PHPUnit is a separate step.

**Package migrations are no longer loaded automatically.** Sanctum 4, Passport 12, Cashier Stripe 15, Spark Stripe 5 and Telescope 5 stop loading migrations from `vendor/`. If the app relied on that, publish them, e.g. `php artisan vendor:publish --tag=sanctum-migrations`, and check the published files against tables that already exist before anyone runs `migrate` (the tables exist; the published migration must not try to create them again on an existing database). Sanctum 4 also needs the middleware class names in `config/sanctum.php` updated (see the guide).

### Migrations: Behaviour Changes That Hit Existing Files

These don't fail loudly. They change what old migrations do when they run again: in CI, in `RefreshDatabase` tests, on a new environment.

**`change()` drops modifiers you don't repeat.** In 10, `->change()` kept existing `unsigned`, `default`, `comment`. In 11 it applies exactly the definition given.

**Incorrect:**

```php
$table->integer('votes')->nullable()->change(); // 11: loses unsigned, default and comment
```

**Correct:**

```php
$table->integer('votes')->unsigned()->default(1)->comment('The vote count')->nullable()->change();
```

Grep for `->change()` and check each against the column's earlier definition. Already-run migrations are unaffected in existing databases; the guide's alternative is `php artisan schema:dump` to squash them.

**`float()` and `double()` lost `$total` and `$places`.** 10: `float($column, $total = 8, $places = 2, $unsigned = false)`. 11: `float($column, $precision = 53)` and `double($column)`. PHP accepts the extra arguments silently, so `$table->float('price', 8, 2)` now means `FLOAT` with precision 8 (single precision) and the 2 is ignored. Money columns belong in `decimal('price', 8, 2)`; changing an existing migration is a schema decision, so report it rather than editing silently. `unsignedDecimal()`, `unsignedDouble()` and `unsignedFloat()` were removed: chain `->unsigned()`.

Spatial types: `point()`, `polygon()` and friends become `geometry()` / `geography()` with `subtype:` and `srid:`. SQLite must be 3.26 or newer.

### Smaller Breaking Changes Worth Grepping

- **Rate limiting is in seconds.** `new Limit($key, $attempts, $seconds)`, `new GlobalLimit($attempts, $seconds)`, `new ThrottlesExceptions($attempts, $seconds)` and `ThrottlesExceptionsWithRedis` take seconds now. `Limit::perMinute()` and friends are unchanged. `Limit::$decayMinutes` became `$decaySeconds`.
- **`casts()` method on the base model.** A model defining its own `casts` relationship or method now collides with `Model::casts()`. The `$casts` property still works; moving to the method is optional.
- **Password rehashing on login.** If the password column isn't `password`, set `protected $authPasswordName = 'custom_field';` on the user model, or set `'rehash_on_login' => false` in `config/hashing.php`.
- **Contracts gained methods** (implementers must add them): `UserProvider::rehashPasswordIfRequired()`, `Authenticatable::getAuthPasswordName()`, `Mailer::sendNow()`, `ConnectionInterface::scalar()`, `BatchRepository::rollBack()`, `Enumerable::dump(...$args)`.
- **Doctrine DBAL methods removed** from `Connection` and `Schema\Builder` (`getDoctrineSchemaManager()`, `registerDoctrineType()`, ...). Use `Schema::getTables()`, `getColumns()`, `getIndexes()`, `getForeignKeys()`.
- **Cache prefixes**: Redis, Memcached and DynamoDB stores no longer append `:` to the configured prefix, so existing keys are not found after deploy. Add the `:` to the prefix if the cache must survive the upgrade.
- **Sync jobs respect `after_commit`** inside database transactions.

### Carbon 3

Laravel 11 accepts Carbon 2 or 3. Composer will usually pick 3; the `diffIn*` change is silent and worth checking before it ships (`carbon-3.md`). If the step should stay small, constrain `nesbot/carbon` to `^2.72` for this step and move to 3 at the Laravel 12 step, where it is required. Ask which the user prefers.

### Rector

`withComposerBased(laravel: true)` (needs `driftingly/rector-laravel`) covers the geometry column rewrite and some test helper changes, and also offers optional modernisation (`$casts` to `casts()`). See `shared/rector.md` for what to keep.
