## Laravel 12 to 13

Source: the official 13.x upgrade guide, checked against `laravel/framework` 12.69 and 13.34 and the 12.x / 13.x skeletons.

### Dependencies

**PHP 8.3** minimum. In `composer.json`:

| Package | Constraint |
|---|---|
| `laravel/framework` | `^13.0` |
| `laravel/tinker` | `^3.0` |
| `laravel/boost` (if installed) | `^2.0` |

The guide also lists `phpunit/phpunit ^12.0` and `pestphp/pest ^4.0`. Laravel 13's test layer supports `^11.5.50 || ^12.5.8 || ^13.0.3`, so a project on PHPUnit 11.5 can take the framework step first and the PHPUnit step separately (`upgrade-php-test-tools`, if installed). Pest pins its PHPUnit version, so for Pest projects Pest 4 is the step that brings PHPUnit 12.

Laravel 13 allows Symfony components `^7.4 || ^8.0` and Guzzle `^7.8.2 || ^8.0`. Composer may pull Symfony 8 (PHP 8.4 only) or Guzzle 8 in with the framework. Packages that require `symfony/*: ^7` keep Symfony on 7.4, which is fine; check the dry run to see which you got. Laravel 13 also depends on `symfony/polyfill-php85`: on PHP below 8.5 it defines global `array_first()` / `array_last()`, which clash with `laravel/helpers` or custom helpers of the same name (the old helper took a callback; the polyfill doesn't). Use `Arr::first()` / `Arr::last()`.

### Don't Copy the New Skeleton Config Wholesale

Two 13 skeleton config values change behaviour on an existing app. The framework's own fallbacks keep the old behaviour when the key is missing, so leaving the app's config files as they are is safe; copying the skeleton's files is not.

**`config/session.php` `'serialization' => 'json'`.** The framework default when the key is absent is `'php'` (`SessionManager`). Switching an existing app to `json` invalidates every active session: all users are logged out at deploy. Only change it if the user agrees and the session holds no PHP objects.

**`config/cache.php` `'serializable_classes' => false`.** With the key absent, `CacheManager` passes `null` and unserialisation is unrestricted. With `false`, no classes can be unserialised from cache: every cached model, DTO or collection comes back broken. If the user wants the hardening, list the cached classes explicitly:

```php
'serializable_classes' => [
    App\Data\DashboardStats::class,
],
```

**Cache, Redis and session cookie name defaults.** If the app relies on framework fallbacks rather than defining `CACHE_PREFIX`, `REDIS_PREFIX` and `SESSION_COOKIE`, the defaults change from `{app}_cache_` / `{app}_database_` / `{app}_session` to `{app}-cache-` / `{app}-database-` / `{app}-session`: the cache looks empty and users are logged out after deploy. Set the three values explicitly to the old ones to keep them.

### Request Forgery Protection (High Impact)

The CSRF middleware is now `Illuminate\Foundation\Http\Middleware\PreventRequestForgery` and also checks the `Sec-Fetch-Site` header. `VerifyCsrfToken` and `ValidateCsrfToken` remain as deprecated aliases (`VerifyCsrfToken extends PreventRequestForgery`).

**Incorrect:**

```php
$this->withoutMiddleware(VerifyCsrfToken::class);
```

**Correct:**

```php
use Illuminate\Foundation\Http\Middleware\PreventRequestForgery;

$this->withoutMiddleware(PreventRequestForgery::class);
```

In `bootstrap/app.php`, `$middleware->validateCsrfTokens(except: [...])` still exists; `$middleware->preventRequestForgery(except: [...])` is the new name. An app-level `App\Http\Middleware\VerifyCsrfToken` extending the old class keeps working but should extend `PreventRequestForgery`. Webhook endpoints and cross-site form posts that were excluded by class name need re-checking against the new origin check.

### Other Breaking Changes

- **`upsert()` with an empty `uniqueBy`** now throws `InvalidArgumentException`, on MySQL and MariaDB too (which ignore the value).
- **MySQL `DELETE ... JOIN` with `ORDER BY` / `LIMIT`** now compiles those clauses; MySQL and MariaDB before 11.8.1 throw a `QueryException` where 12 silently ran an unbounded delete.
- **Queue events:** `JobAttempted::$exceptionOccurred` (bool) became `JobAttempted::$exception` (`?Throwable`); `QueueBusy::$connection` became `$connectionName`.
- **`Container::call()`** respects nullable class defaults: `function (?Carbon $date = null)` gets `null`.
- **Creating a model while it boots** (`new static` inside `boot()` / `boot*()` trait methods) throws `LogicException`.
- **`Str` factories reset between tests.** `Str::createUuidsUsing()` and friends set in one test no longer leak into the next; set them in each test or `setUp()`.
- **Password reset mail subject** default is now "Reset your password" (was "Reset Password Notification"). Tests asserting the old subject fail.
- **`Js::from()`** no longer escapes Unicode.
- **Bootstrap 3 pagination views** are `pagination::bootstrap-3` / `pagination::simple-bootstrap-3` (were `pagination::default` / `pagination::simple-default`).
- **Domain routes** now match before non-domain routes regardless of registration order.
- **Manager `extend()` closures** are bound to the manager: `$this` inside is the manager, not the service provider. Capture values with `use (...)`.
- **Polymorphic pivot table names** inferred for custom pivot classes are now plural; set `$table` on the pivot model to keep the old name.
- **Contracts gained methods**: `Cache\Store::touch()`, `Bus\Dispatcher::dispatchAfterResponse()`, `Routing\ResponseFactory::eventStream()`, `Auth\MustVerifyEmail::markEmailAsUnverified()`, and `Queue\Queue` size methods (`pendingSize()`, `delayedSize()`, `reservedSize()`, `creationTimeOfOldestPendingJob()`).

### Not Required

The 13 skeleton's `User` model uses `#[Fillable([...])]` and `#[Hidden([...])]` attributes instead of `$fillable` / `$hidden`. The properties still work. Rector's Laravel set converts properties to attributes across models, jobs, commands and resources; leave that out unless asked (`shared/rector.md`). The guide's Laravel Boost `/upgrade-laravel-v13` command is an alternative tool, not a requirement.
